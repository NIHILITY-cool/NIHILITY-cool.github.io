用 CSS 变量维护设计令牌

色彩、字体、宽度与圆角为什么集中在一个文件里。

2026年8月12日编程

设计令牌位于 src/styles/tokens.css。组件不直接记忆某个十六进制颜色，而是使用 --bg、--text、--accent 等语义名称。

这篇笔记记录 Miracle 当前的令牌组织方式，以及新增样式时需要遵守的边界。它不是一套通用设计系统，只覆盖个人博客真正反复出现的颜色、字体、宽度、圆角和动效。

为什么使用语义名称

直接把 #c97a7b 写进链接、按钮、进度条和引用线，短期很直观，几个月后却很难回答“这个颜色承担什么作用”。语义变量先描述职责，再把职责映射到具体颜色。

:root {
  --bg: #faf9f5;
  --surface: #f2f0e9;
  --text: #3b3936;
  --text-soft: #77736d;
  --accent: #c97a7b;
  --accent-strong: #a95d61;
}

组件只使用职责名称：页面读取 --bg，正文读取 --text，链接和进度反馈读取 --accent-strong。当主题变化时，组件不需要知道浅色模式和深色模式分别对应什么十六进制值。

修改主题

想换品牌色时，优先修改 --accent、--accent-strong 和 --accent-soft。不要逐个搜索按钮和链接。

三个强调色并不是三个品牌色。它们是一条颜色在不同对比需求下的角色：

  • --accent 用于面积很小的视觉提示，例如列表标记和细线。
  • --accent-strong 用于文字链接、焦点状态和需要更高对比度的控件。
  • --accent-soft 用于选中背景、标记文本和不应抢夺正文注意力的浅色区域。

修改时需要同时检查浅色与深色主题。深色背景上的浅粉色不应该直接复用浅色背景上的暗红色，否则对比关系会反转，链接可能比标题更显眼。

:root[data-theme="dark"] {
  --bg: #1a1917;
  --text: #ede9e2;
  --accent: #d78989;
  --accent-strong: #e0a2a0;
  --accent-soft: #432e2d;
}

修改后的检查顺序

  1. 先看正文链接和键盘焦点是否清楚。
  2. 再看引用、列表标记和阅读进度是否过强。
  3. 检查代码块、表格和详情折叠区是否突然出现另一套色温。
  4. 最后在手机宽度下确认细线与小字号仍然可辨认。

明暗模式

浅色模式与深色模式复用相同变量名。组件只写一次样式，主题切换只改变变量值。

站点默认尊重系统主题，同时允许读者手动覆盖。手动选择保存在本地存储中，页面加载时会在正文绘制前写入 data-theme，避免先闪出浅色页面再切换到深色。

const saved = localStorage.getItem("leisurebits-theme");

if (saved === "light" || saved === "dark") {
  document.documentElement.dataset.theme = saved;
}

主题脚本只负责选择哪组变量生效，不直接修改组件颜色。这样做有两个好处：新增组件时只要使用语义令牌就自动支持双主题；删除脚本时，CSS 的 prefers-color-scheme 仍然可以提供系统级回退。

双主题不是把所有颜色机械反相。需要保持的是信息层级，而不是 RGB 数值之间的数学关系。

字体令牌

字体比颜色更容易产生割裂。中文正文、英文单词、数字和代码往往来自不同字体，如果优先级没有明确规定，同一行会出现高度、粗细和字面大小不一致的问题。

当前详情页分成三组：文章与笔记使用 Noto Sans SC 优先的无衬线阅读栈；手记标题同样使用 Noto Sans SC，手记正文、摘要与日期恢复使用霞鹜文楷，形成清楚但不割裂的编辑层级。代码始终使用 JetBrains Mono。

--reading-sans:
  "Noto Sans SC Variable",
  "Manrope Variable",
  system-ui,
  sans-serif;

--reading-serif:
  "Noto Serif SC Variable",
  "Songti SC",
  serif;

混合文本测试不能只看标题。至少要检查一段包含中文、English、数字 2026、路径 /notes/example 和行内代码的正文，确认基线、标点位置和粗体没有突然跳动。

阅读宽度

宽度令牌描述内容的最大阅读范围，不等于页面容器宽度。文章正文需要容纳较长的技术句子和代码块，笔记更紧凑，手记则通过纸页留白营造连续阅读感。

内容类型正文最大宽度设计目的
文章840px容纳长句、代码和表格
笔记720px保持快速扫描和知识密度
手记纸页844px接近参考站的连续文档比例

这些数字是上限。屏幕变窄后，容器使用固定的页面边距自然收缩，不在手机上强行维持桌面字宽。

特殊文本块

详情页不能只为普通段落设计。真实内容会包含代码、表格、引用、折叠说明、图片和很长的链接。它们必须共享主题颜色与圆角规则，同时不能改变正文主轴。

type ThemeName = "light" | "dark";

export function applyTheme(theme: ThemeName) {
  document.documentElement.dataset.theme = theme;
}
文本块处理原则
行内代码使用浅表面色与细边框，不让底色压过正文
代码块浅色主题使用暖灰底，深色主题使用深底，并保留语言名称和复制按钮
引用只用一条强调色竖线，不添加大号引号装饰
表格允许横向滚动，表头保持低对比背景
折叠区使用原生 details，无脚本也可以操作
为什么不为每种内容块做独立卡片？

卡片会不断切断阅读流。只有代码和可折叠说明确实需要边界，普通引用、列表和表格主要依靠间距与细线建立层级。

约束

初版只保留一个强调色与一套圆角比例，避免页面在扩展中逐渐失去一致性。

新增令牌前先确认它是否会在多个组件中重复使用。如果只是某个页面的一次性尺寸，应留在页面样式中；如果它描述全站稳定角色，才进入 tokens.css。

同一条规则也适用于命名。--red-500 描述颜色本身，--danger 描述用途；--card-gray 把变量绑在某个组件上，--surface 则可以被代码块工具栏、筛选区和页脚共同理解。

最后，令牌不是为了消灭所有差异。文章、笔记与手记仍然需要不同的字宽和阅读语气。令牌负责让这些差异发生在可控范围内，而不是让所有页面看起来完全相同。
